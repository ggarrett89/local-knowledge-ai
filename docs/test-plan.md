# Test plan

## Principles
- Default tests use no network, Ollama or models. They run with `pytest` at the repository root.
- Tests that depend on a real Ollama use `@pytest.mark.integration` and run only with `pytest -m integration`.
- Test data is synthetic and generated inside the test (PDFs created with PyMuPDF in a temporary directory). No real book enters the repository.
- A result is valid only if the command was actually run. The README records only commands that ran successfully.

## Layers
| Layer | What it covers | Tools |
|-------|----------------|-------|
| Unit | config, chunking, hashing, filters, context assembly, reference formatting | pytest |
| Storage | SQLite and Chroma in a temporary directory, persistence after reopening | pytest + `tmp_path` |
| Ingestion | valid, invalid and no-text PDFs, duplicate, change, removal | synthetic PDFs, fake embeddings client |
| Retrieval | filters, empty database, no results, incompatible model | fake deterministic vectors |
| RAG | Ollama unavailable, empty context, sources taken from metadata | fake chat client |
| API | contracts, token, limits, paths, 4xx/5xx errors | FastAPI `TestClient` |
| Web collector | SSRF, redirects, limits, malformed HTML | fake local HTTP server / `httpx.MockTransport` |
| Code | `.gitignore`, exclusions, secrets, source lines | temporary synthetic repository |
| Integration | real Ollama in the VM | `-m integration` |
| Evaluation | Recall@k, citations, latency, memory (Stage 7) | synthetic corpus |

## Requirements matrix
| Topic | Stage | Main cases |
|-------|-------|------------|
| Configuration | 0 | safe defaults, environment override, validation, secret not exposed, no filesystem side effects |
| PDFs | 1 | valid, corrupted, no text, several files, recursive |
| Incremental | 1 | duplicate, change, reindex, remove without deleting the file |
| Persistence | 1 | reopen database and collection and get the same data |
| Embeddings | 1–2 | incompatible model refused, service unavailable |
| Search | 2 | filters by document/category/topic, result limit, empty, redundancy |
| References | 2–3 | correct page, real URL and section, no invented reference |
| RAG | 3 | insufficient context, Ollama down, timeout, nonexistent citations discarded |
| API | 3 | missing/invalid token, path traversal, input above the limit |
| Web | 4 | private/loopback/metadata IPs blocked, redirect outside the allowlist, large response |
| Code | 6 | `.env`, keys, `node_modules`, `terraform.tfstate`, detected secret, source lines |
| Limits | 1, 3 | memory (document processed as a stream), context budget |

## Exit criteria per stage
1. `pytest` at the root passes, with the output attached to the report.
2. Integration tests not run are listed with the reason and the command to run them.
3. README updated and consistent with the commands actually run.

## Stage 0
`pytest` validates the configuration and the categories file. The `Vagrantfile` is validated with `vagrant validate`.

## Stage 1: PDF ingestion
Everything below runs with a deterministic fake embeddings client, real SQLite and real ChromaDB in temporary directories, and PDFs generated by the tests.

| Area | Covered |
|------|---------|
| Config | defaults, env overrides, chunking validation, `.env.example` loads |
| Ollama client | prefixes, `truncate=false`, unreachable, timeout, missing model (no pull), HTTP errors, malformed responses |
| Metadata store | round trip, upsert, filters (category, all topics, status), SQL-injection safety, errors, categories, persistence after reopening, statistics |
| Vector store | provenance without unknown fields, idempotent upsert, delete, prune, persistence, identity and dimension mismatch |
| Chunking | size limit, no text lost, overlap, page provenance per chunk, lazy consumption, no-whitespace text, invalid parameters |
| PDF extractor | pages and numbers, title, corrupted/empty/encrypted files, file never modified, no content in errors |
| Service | provenance and hashes, batch size, streaming, unchanged, duplicate, changed file, forced reindex without stale chunks, no-text PDF, corrupted PDF in a folder, failure mid-document, Ollama down aborts a batch, unsupported/missing files, invalid slugs, recursive `add-all`, remove keeps the file, restart persistence, source directory untouched, logs without document text |
| CLI | every command, exit codes, confirmation on `remove`, new categories, model change refused, `list`/`stats`/`remove` without Ollama, `python -m` entry point |

Mutation check done once by hand: disabling the cleanup of partial chunks, and disabling the pruning of stale chunks, each made the corresponding test fail.

**Also run in the VM (Python 3.10.12)**
- Default suite: 141 passed, 2 deselected.
- `pytest -m integration` against the real Ollama and `nomic-embed-text`: 2 passed (embedding dimension consistency, end-to-end ingestion of a synthetic PDF).
- Manual CLI scenarios (import, unchanged, identity mismatch, missing model, Ollama stopped, retry, reindex, remove) are recorded in the README with their output. They are not automated against a real Ollama.

**Not covered / not run**
- Ingestion was exercised with one real text-based book (473 pages) and verified by hand against the PDF (README "One real book"); this is not automated, and no scanned, multi-column or heavily code-based book has been tried.
- Time, memory and disk were measured once on synthetic text (README "Measured results"); the systematic benchmark is Stage 7.
- Retrieval quality: no search exists yet (Stage 2).

## Stage 2: semantic search
Default tests use a deterministic word-overlap embedder (`BagOfWordsEmbedder`) with real SQLite and ChromaDB, and PDFs generated from a small bilingual synthetic corpus (`tests/corpus.py`, written for this project). The word-overlap embedder proves plumbing, ranking mechanics, filters, references and thresholds; it does not model meaning or other languages.

| Area | Covered |
|------|---------|
| Reference formatting | page, page range, no pages, web, code; unknown fields never invented |
| Models and settings | filter normalization and invalid slugs, empty-filter semantics, retrieval settings and their bounds |
| Vector query | cosine distances (0, 0.4, 1, 2), best-first order, `k` above the count, document filter, empty id list, empty store, provenance rebuilt from storage, dimension mismatch, `k < 1` |
| Retriever | empty/overlong question, `k` bounds, candidate limit and cap, category/topic/source/document filters, filters matching nothing do not embed the question, threshold (boundary kept, per-call override), sorting, de-duplication (identical text, adjacent, cross-document, disabled), `k` after de-duplication, embeddings errors propagate, logs without question or text |
| End to end | right book and page for EN and PT questions, ranking, filters, empty index, removed documents not returned, restart persistence, different embeddings model refused, embeddings service down |
| CLI | ranked output with references, `-k`, JSON schema, filters, no-result messages, `--max-distance`, invalid input, model mismatch, Ollama down, index unchanged by searching, `python -m` entry point |

**Opt-in, real model (`pytest -m integration`, run in the VM, 15 passed in total):** for 10 EN/PT questions the right topic is in the top 3, the top hit is correct for at least 80% per language, a Portuguese question finds the Portuguese book, and the worst answerable distance is below the best unanswerable one on the synthetic corpus (0.329 vs 0.357).

**Measured by script, not asserted (README "Distances and the relevance threshold"):** distance distributions on a real book, threshold trade-offs, keyword-relevance proxy, search latency, and a check that hit text sits on its cited pages.

Mutation checks done by hand: ignoring the filters, comparing the threshold the wrong way, and reversing the vector-store order each made tests fail.

**Not covered**
- Labelled ground truth, Recall@k on real data and answer quality: Stage 7.
- Books other than one clean text-based English book; scanned or code-heavy books.
- Lexical (exact-term) queries; hybrid search does not exist.

## Stage 3 (current): grounded answers and HTTP API
Default tests use a scripted fake chat client, a word-overlap embedder, real SQLite and ChromaDB in temp directories, and FastAPI's `TestClient`. No Ollama and no model is involved.

| Area | Covered |
|------|---------|
| Chat client | request shape, options, empty/malformed/non-JSON replies, unreachable/timeout, missing model without pulling, HTTP errors, usage numbers, prompt that cannot fit refused before sending, silent truncation detected, model catalog |
| Settings | defaults, bounds, token minimum length, empty token = disabled |
| Context and prompt | budget (best passage always kept), numbering, delimiter forgery neutralized, rules in the system message and passages in the user message, the refusal word not repeated in the reminder |
| Verification | refusal recognition, `Inference:` split (EN/PT/markdown), citation validation, URL and page redaction against cited pages, grounding (keep, move, remove, paraphrase, invented references not diluting support, a clearly better passage taking over), invented identifiers |
| RAG service | cited answer with metadata sources, invented references removed, wrong attribution repaired, statement in no passage flagged, `unverified`, inference apart, refusal paths, no passages = no model call, budget limits passages, injection text stays inside its passage, model failures propagate, logs without question/answer/passage text |
| API | health variants, search and chat contracts, filters, validation, generic 503/502/409/500 without leaks, documents never expose absolute paths, authentication (missing, wrong, malformed, disabled, before body validation, constant-time call), ingest (relative/absolute, folder, force, traversal, symlinks, missing, problem files, Ollama down, single-flight lock, lock released on failure), delete (confirmation, file kept, lock), body limits (declared and streamed), privacy (logs, token never returned), exactly the required endpoints, start-up and shutdown, fail-fast on embeddings mismatch, default binding |
| Storage | the metadata store used from several threads |
| Ingestion | `confine_to_root` skips symlinks that leave the folder |
| Scripts | `evaluate_rag.py` and its question file |

**Opt-in, real models (`pytest -m integration`, run in the VM, 19 passed):** the four Stage 3 tests assert only invariants that must hold for any output (sources are retrieved passages, no URL or page the passages cannot back, an unrelated question is not answered from the library, a planted instruction does not hijack the answer). Answer quality is measured by `scripts/evaluate_rag.py`, not asserted.

**Measured by script (README "Measured results (Stage 3)"):** 16 questions on the real book, run five times across prompt variants, including a cold start. Findings that changed the code: misattributed citations, an invented file name, missing Portuguese citations, over-refusal when the refusal word was repeated, and Ollama silently truncating long prompts.

Mutation checks done by hand: page-number redaction, citation validation, the no-passages guard, the token check, path confinement, delimiter neutralization, citation grounding, the identifier check, the pre-send size check, truncation detection and refusal recognition were each disabled and made tests fail. The last one first survived (a second path produces the same result), so a test now pins which path ran.

**Not covered**
- Answer correctness. The checks verify references and wording, not truth; there is no labelled ground truth (Stage 7).
- More than 16 questions, one book, mostly English; scanned or code-heavy books.
- Variation between runs: individual questions flipped between runs with identical settings.
- Token-dense text in the context-window guard.
- Concurrent users: one request at a time was exercised against the real model.
